# 0027 - The application icon is a project-owned SVG built offline to a committed multi-size ICO

- Status: accepted
- Date: 2026-10-31 (M6 change `add-app-icon`)
- Source: change `add-app-icon` (design D1-D5)

## Context and problem

`blackgrid.exe`, the installer and its uninstall entry show Flutter's default `windows/runner/resources/app_icon.ico`, which holds only 16, 32, 48 and 256 px images. `Runner.rc` embeds that file as `IDI_APP_ICON` and `blackgrid.iss` takes `SetupIconFile` from it, so replacing it covers all three surfaces. Releases are now published from tags (ADR-0026), so Blackgrid needs its own icon before the first public beta, with a source that can be rebuilt and a check that the shipped executable carries it. The user generated four concept images with ChatGPT. ADR-0023 forbids committing such concept images for map marker icons, so this second project-authored asset family needs its own record.

## Decision

- **The source is a project-owned SVG with a provenance record (D2).** `windows/runner/resources/app_icon/` holds `app_icon.svg`, an optional `app_icon_small.svg` used for the 16, 20 and 24 px images, and `provenance.json`: `schemaVersion: 1`, `author`, `method` (`hand-authored` or `ai-assisted`), `tools`, `date`, `pickedCandidate`, `pickDate`, `concept` (the candidate PNG it redraws, or null) and a `sha256` for each source and for the `.ico`. Unknown fields are rejected, as in ADR-0023. The folder is not a Flutter asset and is never bundled. Candidates live in `docs/design/app-icon/candidates/` (`concepts/*.png`, `vector/*.svg`) with one `provenance.json` entry per file. Both folders are stored `-text` so hashed bytes survive checkout.
- **Rasterize in the Flutter test host, encode in plain Dart (D1).** `tool/app_icon/` has a `dart:ui`-free core (ICO encoder and parser, provenance, candidate discovery, sheet HTML) under plain unit tests, and one Flutter-host entry, `tool/app_icon/render_host_test.dart`. The host compiles each SVG with the map marker flags (`compileIconSvg`, `encodeSvg` with warnings as errors), draws the picture at each size with `toImage` under `tester.runAsync`, and reads it with `ui.ImageByteFormat.rawStraightRgba`. ICO bitmaps and PNG store straight alpha; the premultiplied `rawRgba` would darken every anti-aliased edge. The same bytes feed the ICO and the comparison sheet. `mise run icon:build` and `mise run icon:sheet` run the host with `--dart-define=APP_ICON_MODE=build|sheet`; without the define it fails and writes nothing. The host lives outside `test/`, so `mise run test` and CI never run it.
- **The comparison sheet shows the shipped rasters (D3).** `icon:sheet` writes one self-contained `build/app-icon-preview/index.html` (`.tmp` then rename, PNGs as data URIs, no external URL), one column per recorded candidate, at most 12, at all ten sizes on a light (`#F3F4F6`) and a dark (`#11161A`) background. Vector columns show the exact ICO rasters at 1× and 4× pixelated; concept columns show the PNG scaled by the browser and say so. An unrecorded candidate, a candidate that fails to compile or more than 12 candidates end the run before anything is written.
- **ICO layout (D4).** Ten images in ascending order: 16, 20, 24, 32, 40, 48, 64, 96, 128 and 256 px. Below 256 each is a 32-bit BGRA `BITMAPINFOHEADER` DIB (height doubled, rows bottom-up, an all-zero AND mask); 256 is PNG. Directory planes and bit count equal the DIB header's, because `rc.exe` rebuilds the group entries from the image headers. The encoder is our own: `image`'s `IcoEncoder` writes every entry as PNG.
- **Hash binding instead of regeneration (D2).** Only `icon:build` writes the `.ico` and the record's hashes: it compiles every source first, renders all sizes, then writes the `.ico` and then the record, each through `.tmp` and a rename. The offline icon test (`mise run test`, so CI) checks the committed `.ico` (ten sizes, 32 bpp, DIB below 256, PNG at 256, no fully transparent image, not Flutter's default SHA-256) and fails when a source or the `.ico` differs from its recorded hash, naming `mise run icon:build`.
- **The bundle check compares the executable's icon with the committed ICO (D5).** `tool/vision/pe.dart` gains `readIconGroup()`, outside `readPe()`'s single try so a malformed icon resource never hides imports or version data. It reads the first `RT_GROUP_ICON`, at most 32 entries, and resolves each `nID` to its `RT_ICON` bytes, every read bounds-checked. `bundle:check` gains an `app-icon` step after `map-marker-icons`: images are keyed by (width, height, bit depth), a stored 0 read as 256; a duplicate key on either side, a key on one side only, unequal bytes or an unreadable group fails the step and names it. `rc.exe` copies image bytes verbatim, so byte equality holds. CI runs it on every PR (ADR-0024). `setup.exe`'s icon is covered by a static test of `blackgrid.iss` (`SetupIconFile` resolves to the committed `.ico`, `UninstallDisplayIcon={app}\blackgrid.exe`) and by the user's install check.
- **Scope difference from ADR-0023.** Its provenance shape, compile flags and "no third-party art traced or used as a style reference" rule apply here. Two of its rules are scoped to map marker icons and deliberately not applied: "a concept image from an image-generation tool is not committed" and "a concept names a prompt record". The app-icon concepts are the user's own ChatGPT generations, committed as a design record under `docs/` and never bundled; only the SVG redraw feeds the shipped icon. A prompt is recorded when the user supplies it, else it is null.

## Rejected alternatives

- **A pinned external rasterizer (resvg or Inkscape), downloaded and hash-checked like Inno Setup:** a second pinned-download path for a one-off asset, with anti-aliasing that differs from how the app draws its SVGs.
- **Per-size PNGs exported by hand from an editor:** no reproducible build from the source.
- **Byte-identical regeneration in CI:** needs the Flutter host in CI and ties the gate to Skia's anti-aliasing staying bit-stable across engine upgrades. Hash binding catches the real failure, a source edited without a rebuild.
- **The browser rendering the SVGs on the sheet, as the marker sheet does:** the user would judge the browser's 16 px raster, not the one that ships.
- **`image`'s `IcoEncoder` (PNG for every size):** PNG small entries are the less-tested path for `LoadIcon`, `rc.exe` and Inno Setup's wizard; Windows' own icons use DIBs below 256.
- **Checking only `Runner.rc` and the `.ico` statically:** misses a stale build or a rewired `.rc`; the exit criterion names `blackgrid.exe`.
- **Checking `setup.exe`'s embedded icon:** Inno's loader is a separate PE whose bitness and icon re-encoding are not established.

## Consequences

- Changing the icon means editing the SVG, running `mise run icon:build` and committing the `.ico` and `provenance.json` together; the icon test fails until both are committed.
- A bundle built before an icon change fails `app-icon` until rebuilt. That is intended.
- Windows may show a cached old icon after an upgrade; the design record notes `ie4uinit -show`.
- **Reversal cost:** low. The renderer sits behind the core's straight-RGBA interface, the record has a `schemaVersion`, and the bundle step is one named step. No shipped runtime code or stored user data depends on any of it.
