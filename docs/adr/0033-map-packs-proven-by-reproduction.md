# 0033 - Map packs are proven by reproduction, not pinned toolchain versions

- Status: accepted
- Date: 2026-11-02 (change `unpin-map-toolchain`)
- Supersedes: 0005 ([ADR-0005](0005-native-map-prepared-packs.md)), three statements only: the consequence "old generations are kept", the consequence that `pubspec.yaml`'s tile directories are "generated by `prepare.dart assets`", and the runtime bullet "The loader checks structure and versions". The rest of ADR-0005 stays in force: offline preparation, immutable content-addressed generations, the atomic `active.json` pointer, a runtime that trusts the bundled bytes and reads no artwork in the loader.
- Source: change `unpin-map-toolchain` (design D1-D8)

## Context and problem

The map packs (ADR-0005) are built offline with `vector_graphics_compiler`, `xml` and `image`, and drawn at runtime by `vector_graphics` and `vector_graphics_codec`. Until this change each of those versions was a gate: the manifest had to name compiler `1.3.0` and runtime `1.2.3`, and the validator compared every compiled vector against a hand-kept table of hashes for that compiler. The weekly dependency update could not bump any of these packages without a hand edit and a new 67 MB generation, even when no byte changed. A version label also proves nothing: what matters is that the installed toolchain still produces the committed bytes, and that the shipped runtime can decode them.

## Decision

- **Provenance, not gates (D1).** Each manifest records the five resolved versions from `pubspec.lock` under `toolchain`. The record says what built the generation; nothing compares it with anything. A lock missing one of the five packages fails before any write.
- **The app accepts by vector format (D2).** The manifest records `vectorCodecFormat`, read from the compiled `.vec` headers (magic `62 2d 88 00`, then the format byte). The validator checks every header against it. The loader accepts a pack whose format equals `preparedVectorCodecFormat`, a constant tied by test to the resolved codec, and refuses any other with a message naming both formats and `mise run maps:rebuild`. The loader checks, in order: manifest schema, preparation version 3, vector format.
- **Reproduction replaces the hash table (D3).** Compilation runs twice and fails if the two outputs differ. Validation recompiles every `.compiler.svg` with the installed compiler and requires byte equality with the committed `.vec`.
- **The committed generation is its own frozen input (D4).** It carries its frozen evidence and every source the build reads. Before rebuilding, the tool verifies that the manifest hash equals the generation id and that the files equal `manifest.outputs`.
- **Two commands (D4, D5).**
  - `mise run maps:check` rebuilds the active generation in a temporary folder and compares manifests without `toolchain`. On success it prints `Map pack <id> reproduced byte-identically with <the five versions>.`; on a difference it prints a per-map, per-floor change report and fails. It is a gate in hosted CI, after `test`, and adds that step to ADR-0024's offline gates.
  - `mise run maps:rebuild` refuses leftovers of an interrupted promotion, then rebuilds, validates, reports, promotes, rewrites the marked map asset block in `pubspec.yaml`, and deletes every other generation. When anything other than `toolchain` changed, files or manifest values, it says the owner must check the listed maps in the app before merge.
- **Identical bytes need no rebuild (D6).** A bump that the check passes keeps the existing generation, whose manifest still names the versions that built it.
- **No fallback generation (D8).** The app loads only the generation `active.json` names and never falls back; a broken pack is a load error in the map area. The working tree keeps only the active generation; a rollback is a git revert. Only preparation version 3 validates or loads. A failed promotion still leaves the current generation untouched.
- **Upgrade procedure.** AGENTS.md tells the dependency agent: after bumping a map toolchain package, run `mise run maps:check`; if it fails, run `mise run maps:rebuild`, commit the result, and mark the PR "artwork changed: owner check". This is a regeneration step like build_runner, not a code change.

## Rejected alternatives

- **Keep version gates, read from the lock.** Every patch bump would force a new generation with no byte changed.
- **A hand-bumped pack format number.** Nothing ties it to what the runtime decodes.
- **Regenerate the hash table per compiler version.** A hand-kept table proves nothing that a sub-second recompilation does not prove directly.
- **Rebuild from the raw acquisition folder.** It exists on one PC and CI cannot reach it.
- **Keep one previous generation as a fallback.** Nothing reads it; git history is the rollback.

## Consequences

- **Map toolchain bumps are routine.** CI proves on every PR that the installed toolchain reproduces the committed pack.
- **A codec format change is explicit.** It fails the codec-format test and needs `preparedVectorCodecFormat` updated together with a rebuilt pack.
- **Changed artwork always reaches the owner.** The rebuild report names the maps and floors to check.
- **Older generations no longer load or validate.** Restoring one means reverting the whole change.
- **Reversal cost:** low. Adding a version-equality check later is one comparison, and a revert restores the old loader, validator and generation together.
