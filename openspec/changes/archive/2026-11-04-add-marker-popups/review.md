## Findings

### Critical (blocking)

### Moderate

None found. The amended planning contract resolves the evidenced seams without requiring another user decision. The following checks support that conclusion; statements about new groups describe their required implementation, not work already delivered.

- **Amendment coherence and authorization.** Proposal scope and S2, design D1/D4/D6 and their summary rows, the summary-only specification, and groups 5–7 agree: remove marker raw Details entirely, retain no popup/raw-preview cache, consume frozen bundled boss facts, correct generic equal-distance hit ordering, and isolate popup keyboard input. D4 explicitly supersedes the original user decision rather than silently rewriting its provenance. `tasks.md` expressly marks groups 1–4 and their earlier integration evidence as historical attribution, not acceptance for retired Details behavior. The fresh review is required before implementing groups 5 and 6 even though its task appears under the integration heading.

- **Complete removal rather than hidden diagnostics.** The current chain is concrete: `_markerDetailsExpanded` in `map_screen.dart:227-228,355-359`, workspace constructor properties and `_buildMarkerPreview` in `map_workspace.dart:49-63,381-396`, popup wiring at `:629-640`, and Details builders/controls in `marker_popup.dart:13-38,160-266`. `marker_preview.dart` is a dedicated raw-data writer, not the summary source. Group 5.2 requires deleting this implementation, expansion/callback state, related callers, preview-only tests and obsolete assertions without shims; the specification independently forbids the control and raw fields. It does not merely collapse or stop rendering an otherwise retained preview.

- **Caller and test cleanup includes less obvious consumers.** Besides the production workspace and popup, direct constructors occur in `marker_popup_layout_test.dart`, `marker_popup_quest_test.dart`, the isolated widget preview, and the painting/zone-label workspace fixtures under `test/ui`. The design's all-caller migration and group 5.2's “all related callers” cover these, including callers outside the primary popup suite. The existing counting-builder/raw-preview fixture in `marker_popup_layout_test.dart:279-353` is retired behavior; zero/tiny/scaled/corner/tether/Close geometry tests in that same file remain useful and require constructor migration, not deletion of the entire suite. Group 5.1 explicitly replaces the preview-dependent long-content case with genuinely long player-facing summary content, while group 5.3 retains a summary-only isolated widget preview. This distinguishes the obsolete raw-preview machinery from the useful `@Preview` entry point and avoids leaving its synthetic raw-data builder or no-op expansion callbacks as dead scaffold.

- **Prepared facts and other surfaces' Details remain intact.** `presentMarker` directly consumes `PreparedMarker.details` and `.source` for quest text, transferred items, keys, boss chances and same-map switch relationships (`marker_presentation.dart:31-109,169-194`). The loader stores those fields independently of the diagnostic writer (`prepared_map.dart:642-681`). Proposal scope, the summary-only requirement and group 5.2 explicitly retain them, so removing `marker_preview.dart` does not authorize stripping prepared data. The conditional Details contract in `player-facing-text` still governs surfaces that offer Details; it does not compel a marker popup to offer one. The shared `DetailsSection` in `theme.dart:224-282`, Scanner Details wiring found in the caller inventory, Map saved-file-input expansion, and saved-pin controls are not obsolete marker state. The proposal and tasks expressly preserve those contracts.

- **Nearest, inclusive radius and paint-order ties are separately specified.** The painter draws built-in badges in forward visible-inventory order (`map_workspace.dart:743-758`). The current badge hit loop walks that inventory in reverse but overwrites its candidate on `candidate <= distance` (`map_controller.dart:641-651`), which explains why a lower-painted equal-distance badge currently wins. D6 and group 6 require retaining the first reverse-order candidate only on ties, while replacing it for a strictly nearer eligible badge. They separately preserve admission at exactly the radius and exclusion beyond it. This prevents the common incorrect fix of changing the sole comparison to strict inequality and thereby losing the first exact-radius hit. The new synthetic regression explicitly covers co-located and equal-distance badges across categories, nearer hits, exact-radius inclusion and outside-radius exclusion. Existing hovered/selected outline fallback remains unchanged; no boss-category priority or pin-selection redesign is authorized.

- **Frozen boss chance and absence of implicit fetch/cache.** Offline preparation copies `boss['spawnChance']` into each location marker (`tool/maps/pack.dart:1596-1614`), establishing that the value is boss-wide, not a location probability. Current pure presentation reads that prepared value and validates finite numeric range before rendering a percentage (`marker_presentation.dart:88-100`); existing summary tests cover 35%, out-of-range and nonfinite values. D1/D6 and S2 explicitly retain the bundled snapshot and prohibit REST refresh, pack enrichment/regeneration and selection-triggered network work. No claim that the observed live 57% should replace the bundled 60% is made. Existing catalog storage/cache ownership remains with `CatalogController`, not a new popup cache. Its mode-change clearing and generation fences (`catalog_controller.dart:65-103,130-175`), plus the consumer mode guard and notifier listening, support matching last-good names without initiating refresh. Existing popup catalog tests count requests around selection/publication/failure; the amendment retains that coverage rather than removing it with the preview-only tests.

- **Keyboard isolation preserves control input and existing map behavior.** The ancestor workspace handler presently pans on all four arrows and handles Home, zoom keys and C before its pin/browser/delete/Escape branches (`map_workspace.dart:328-378`). The popup currently fences Enter/N/Delete/Escape but not those navigation keys (`marker_popup.dart:137-155`), so the requested correction has a concrete route to address. The amended design requires child controls to receive applicable keys first and the ancestor map handler to ignore map shortcuts while focus is inside the popup. It does not authorize indiscriminate pre-child consumption. Group 5.1 adds all-navigation coverage, explicitly ArrowLeft and child-handled input, while retaining Escape/modal precedence and uncovered-map navigation. Existing keyboard tests currently use the Details control (`marker_popup_test.dart:668-707`); group 5.2's obsolete-assertion and caller cleanup therefore requires adapting them to the surviving controls, not keeping a fake Details control for tests. The labelled keyboard Close test already provides an observable control action and post-dismissal map-focus proof (`:709-752`). Map help's modal Escape still closes only help, as required by the preserved main specification.

- **Ownership, ordering, failure and resource bounds remain coherent.** Controller-owned selection is independent of viewport culling; the current accessor and shared eligibility predicate are explicit (`map_controller.dart:520-549,609-620`). Search dimming does not invalidate it; floor/category/quest or content replacement does. The design preserves browser map/content-generation and current-inventory rechecks, matching catalog publication, pin/marker mutual exclusion and linked-highlight clearing. Popup placement continues to use the existing transform and measured viewport constraints, not a second coordinate system or map movement. Removing diagnostics reduces state/work rather than introducing a queue, worker, timeout, retry or new cache. Summary work remains synchronous over the selected prepared marker and existing map inventory. A hidden offscreen or unusably constrained bubble keeps eligible selection until viewport recovery; an ineligible selection clears permanently. Those outcomes have explicit controller/widget test mappings.

- **Test map and evidence boundaries.** Every current scenario has a named automated test mapping; no mechanically assertable popup behavior is delegated to a user feel check. The amendment marks its new tie, summary-only, navigation-isolation and replacement long-summary-scroll rows red and requires targeted MCP tests followed by integration analysis/tests and artifact/release-note validation. Existing geometry, outline/hazard, linked-highlight and cursor-anchor/hit-radius proofs are explicitly preserved. The reported user feel test on Release `0.7.0+403`, head `7bd9a60`, is correctly described as general feel only, not the milestone-wide M8 real-map readability judgment. Neither that report nor the earlier green rows are treated here as execution evidence for groups 5–7.

- **Architectural fit and documentation.** No new notifier framework, persistence format, runtime map-data source, badge-art contract or dependency is proposed. ADR-0002's state/composition pattern, ADR-0005/0033's offline immutable pack boundary and ADR-0023's painter-owned badge styling remain intact. Group 5.2 covers the currently stale README Map controls Details row and applicable API documentation; the same all-obsolete-content instruction covers workspace help/footer wording. Proposal release notes describe the intended summary-only delivered feature and remain the ADR-0029 release-note authority. No release/version bump is part of the amendment.
