# Windows Release AOT and frame ownership

[Hosted run 45849847761](https://github.com/sh1ny/blackgrid/actions/runs/45849847761) passed analysis, fast tests and map reproduction, then failed the Windows Release build at `linearscan.cc:3013`. The local Windows Flutter assemble target reproduced the failure: the compiler trace stopped after `Precompiling optimized function: …CapturePolicy_capture`, followed by `aot_elf_release` exit `-1073740791`.

After the gaming check exited 0, the same command ran before and after the edit with a temporary output directory and the failed run's build version:

```sh
version=$(printf %s BLACKGRID_VERSION=0.10.0+515 | base64 -w0)
mise exec -- flutter --verbose assemble --output="$scratch" \
  --define=TargetPlatform=windows-x64 --define=BuildMode=release \
  --define=TargetFile=lib/main.dart --define=ExtraGenSnapshotOptions=--trace-compiler \
  --dart-define="$version" release_bundle_windows-x64_assets
```

After `reject` captured the declaration-initialized frame ID instead of the switch-assigned `RawCapture`, the trace showed `CapturePolicy_capture` compiling successfully, then `aot_elf_release`, `windows_aot_bundle`, and `release_bundle_windows-x64_assets` completing. Assemble exited 0. The trace flag is diagnostic; the hosted build command and gates are unchanged.

`mise run analyze` reported no issues. `mise run test` passed 3,651 root Flutter tests and 110 progress tests, including `capture_policy_test.dart` and `capture_service_test.dart`. The existing rejection release and successful handoff assertions were not changed. No app, game, installer or native qualification suite ran locally. The unchanged hosted job owns the complete Windows Release bundle, qualification and packaging checks; the owner alone runs installation and first launch.
