## Findings

### Critical (blocking)

None.

### Moderate

**M1. Rebuild changes that show on screen but leave every output file unchanged trigger no owner check.** In D4, the rebuild's "Artwork changed: the owner must check the maps…" line fires only "if any file other than `manifest.json` changed". The spec scenario "Only provenance changes" fixes the same rule. But a rebuild can change what the app draws while every output file stays byte-identical:
- `rebuildCandidate` computes the raster maps' `displayCrop` from `image` alpha decoding (pack.dart:440-470). The runtime reads it (prepared_map.dart:57).
- Tile `empty` flags and `alphaBounds` come from the same decode (pack.dart:620-650), and the runtime skips `empty` tiles (prepared_map.dart:230).
- `layerOrder` (from `xml` through `svgLayerOrder`), component `effects` and `vectorCodecFormat` are manifest values, not output files.

Raster tiles are byte copies of hash-locked sources, so in a rebuild from the committed generation they can never change bytes. On Labs, Icebreaker and Labyrinth, the realistic visible effect of an `image` bump (this change moves image 4.8.0 → 4.12.0) is therefore a changed crop or empty flag with no changed file. `check` would list the differing manifest keys and fail. `maps:rebuild` would then promote the new generation, report "no artwork file changed", and the dependency agent would commit it without the owner check that AGENTS.md is meant to require. `packChangeReport` also attributes only output paths, so these differences have no per-map line either.

**M2. The "Interrupted earlier promotion" scenario claims existing behaviour the code lacks, and pruning can silently delete the leftover.**
- `promoteCandidate` refuses only the staging folder of the version it is promoting right now, `versions/.$version.staging` (pack.dart:1455-1459). A leftover from a promotion with a different id is not detected. That happens whenever the toolchain or inputs changed between the interrupted run and the next one.
- Neither guard names a path. The messages are `'Interrupted staging directory requires explicit inspection/removal'` and `'Interrupted active pointer requires explicit inspection/removal'`.
- The `active.next.json` check runs only after the new generation was already copied into `versions/<id>` (pack.dart:1483-1489), so promotion has already written to `versions/` before it refuses.
- D4 and D8 then delete "every folder under `versions/` other than the new active generation". A `.<other-id>.staging` leftover is such a folder, so it is deleted without anyone inspecting it. That contradicts the spec's "refuses to promote and names the leftover path, as promotion already does" and the failure table row "The existing guards refuse the next run and name the leftover".

As written, that THEN cannot be asserted against the planned code.

**M3. D8 contradicts in-force ADR-0005, and the design records no supersession.** ADR-0005's Consequences say "Updating artwork is an offline tooling step that produces a new generation; **old generations are kept**" and "`pubspec.yaml` lists every tile directory, generated by `prepare.dart assets`". Its runtime bullet says "The loader checks structure and versions".
- D8 deletes the old generations on every `refresh`.
- D5 moves the pubspec block to `refresh`.
- D2 replaces the version check with a vector format check.

The design's ADR section says ADR-0033 only "refines" the runtime bullet: "ADR-0005 stays in force; no supersession". The architecture index already has a convention for this case ("Partly superseded by …", and a `Supersedes` column). Without it, the ADR index still states retention as an in-force decision while the tool deletes generations, and a later reader of ADR-0005 has no pointer to the change.

### Suggestions

1. **D4's `refresh` bullet reads out of order.** It says "…it deletes every folder under `versions/` other than the new active generation (D8). It then rebuilds into `.dart_tool/maps/refresh-<ts>/`…". Read literally, pruning comes before the rebuild. The spec's order is correct. Reorder the bullet as: markers → `verifyCommittedGeneration` → rebuild → validate → report → promote → pubspec rewrite → prune → delete the candidate.
2. **Order the loader checks so the v2 refusal test can assert its message.** A v2 manifest also has no `vectorCodecFormat`. If the format check (D2) runs before the `preparationVersion == 3` check (D8), the converted `map_scene_test.dart:129` fixture fails with "Pack vector format is not recorded." instead of the "Older preparation version" message the spec requires, which names version 2. State the order: schema, then preparation version, then format. Also state what a non-int `vectorCodecFormat` produces, because `unsupportedVectorFormatMessage` takes an `int`.
3. **Make the spec scenarios use the printed names.** The report line is `<map id> <floor id>: <n> changed file(s)`, so it prints `woods Ground_Level` and `thelab First_Level`. The scenarios say "Woods" and "Labs". Use the ids. Also note in D4 that empty-tile witnesses (`evidence/tile-alpha/<sha>.png`) are shared across floors and land in `other`. A visible-to-empty tile flip then shows as one removed path under the floor plus one added path under `other`.
4. **Name the stale `prepare.dart` usage lines.** Lines 46-63 of `tool/maps/prepare.dart` still say "compile is a separate pinned pure-Dart adapter", "Reviewed Interchange compiler/payload identities avoid recompilation", "Existing published preparation-v2 three-map packs remain readable" and "promote retains prior versions". The proposal says only "plus the usage text". Name these lines so that none of them survives.

## Verdict

VERDICT: APPROVE_WITH_CHANGES

Re-check of round 2 (same reviewer). Only the Required Changes and Suggestions were re-checked, against design.md, proposal.md, spec.md and the code.

- **M1: applied.** D4 now has two parts in `packChangeReport`. *Files* attributes output paths. *Manifest values* attributes floor values (`empty`, `alphaBounds`, `effects`) to the floor, map values (`displayCrop`, `layerOrder`) to `(map id, -)`, and other top-level keys to `pack`. `toolchain` is never reported. The report returns "anything other than `toolchain` differs", and refresh step 4 shows the owner-check line on that result. In the spec, "Only provenance changes" is now narrowed, and the new scenario "Manifest values change without a file change" (`thelab: manifest values changed`) can be asserted.
- **M2: applied.** D4 adds a leftover precheck in `check` and `refresh`. It runs first, finds `active.next.json` and any `versions/.*.staging` folder whatever its id, names the path and writes nothing. The design states correctly that this check is new compared with `promoteCandidate` (pack.dart:1455-1459, 1483-1489). Step 7 of the prune deletes only folders named with a 64-character lowercase hex id other than the active one, so staging folders, whose names start with `.`, are never deleted. The spec scenario, the failure-table row, the concurrency note and the ledger row are all updated.
- **M3: applied.** ADR-0033 partly supersedes ADR-0005 for the three statements: retention, the source of the asset list, and the loader's version check. The header follows ADR-0029 (`Supersedes: 0005 (…), those three statements only`). The index wording matches the ADR-0009/0029 rows of architecture.md. The proposal Impact agrees.
- **Suggestions 1-4: applied.** Refresh has a numbered 1-8 order with pruning after the promotion and the pubspec rewrite. The loader order is schema → preparation version → format, and a format value that is not an int counts as not recorded. The scenarios use map ids (`woods Ground_Level`, `thelab First_Level`). The `other` note for the empty-tile witnesses is added. Proposal lines 46-63 name all four stale usage lines.
- **Note (no action):** the Risks row "A compiler update changes output…" still says that `refresh` "reports changed artwork files". It is accurate but narrower than D4 now is. Updating it to "changed files and manifest values" is optional.

## Required Changes

1. (M1) Base the owner check on any manifest difference, not only on changed files.
   - In D4, `packChangeReport` also attributes manifest differences outside `outputs`, `toolchain` and `vectorCodecFormat`'s provenance role. Differences per map (for example `displayCrop` or `layerOrder`) go under the map, and differences per floor (tile `empty`/`alphaBounds`, component `effects`) go under the floor.
   - The `Artwork changed: the owner must check…` line fires when any manifest content other than `toolchain` differs.
   - In the spec, narrow "Only provenance changes" to "identical apart from the toolchain record". Add a scenario: a rebuild that changes Labs' `displayCrop` with no file change reports Labs and requires the owner check.
2. (M2) Before any rebuild, `refresh` (and `check`, read-only) scans `assets/maps/` for any `versions/.*.staging` folder and for `active.next.json`, and fails naming the path.
   - Pruning deletes only folders whose names are 64-hex generation ids other than the active one. It never deletes a staging folder.
   - Rewrite the spec scenario "Interrupted earlier promotion" and the failure-table row so they name this new precheck instead of "as promotion already does". Then the THEN, "names the leftover path", is assertable.
3. (M3) In the design's ADRs section, ADR-0033 partly supersedes ADR-0005:
   - the "old generations are kept" consequence: replaced by "only the active generation is kept; git history is the rollback";
   - the "generated by `prepare.dart assets`" consequence: replaced by the `refresh`-owned block;
   - the runtime "structure and versions" bullet.

   Record it in the `openspec/architecture.md` ADR index under the existing "Partly superseded by" convention.
