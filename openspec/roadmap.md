## Now: M4.5 - player-facing polish, item icons and own map markers

Runs before M6. M4's `add-map-scan-snapshot` already leaves Map with one scan card. Decided with the user on 2026-10-18 after their live tests on `5d3f7d0`: the Map rail shows information players will not read in a raid, says the same thing twice and uses developer terms, and the markers are placeholder rings. Item icons come from tarkov.dev like the reference companion's, but Blackgrid draws its own marker icons: the tarkov.dev marker set the reference companion uses is MIT in name, but its originals came from the Tarkov wiki (`the-hideout/tarkov-dev` commit `bb40b16`), so their rights are unclear.

**Exit criteria:**
- Map saved-file inputs sits at the bottom of the rail, collapsed by default. (agent for widget state; user for the in-raid read)
- The decision card and history rows show the item's icon, downloaded from tarkov.dev once and kept in a local cache. The previous item's icon never sits next to a new item, and the generic icon shows while loading, offline or when the item has no picture. Service tests prove one download per item, no time-based expiry, revalidation at most every 30 days, and no retry storm after a failure. (agent; user for the live look)
- Every marker category draws its own Blackgrid-authored icon. Selection, dimming, highlighted exits and saved pins still work. Each icon file has its provenance recorded, and no third-party marker art ships. (agent)
- Marker preferences is a uniform grid of clickable icon tiles with player-facing labels. Show all, Hide all, search and the quest filters keep working. (agent; user for the look)
- Requirements & uses rows name their source: a craft shows its product, count, station and level, a barter its offered item, trader level and unlocking task, a hideout row its station level. No raw tarkov.dev id appears when a name resolves, a missing name falls back to the id without dropping the row, and optional crafts and barters group after the obligations. Older cached catalog projections still load. (agent; user for the read)
- Player-facing strings use plain language: no raw enum names or internal category keys. Developer detail (scan evidence scores and timings, source authority) sits behind a collapsed Details section or a diagnostics setting. (agent for the string inventory; user for the read)

**Changes** (in order; each about one PR):
1. `polish-map-rail` - the Active map picker on its own row, and Map saved-file inputs moved to the bottom and collapsed. Independent.
2. `add-item-icons` - shows the item's own icon on the decision card (Scanner and Map) and on history rows, the way the reference companion does. Keeps the catalog's `iconLink`, accepting only HTTPS links on `assets.tarkov.dev` with no query. Downloads only when an item is shown, never a bulk prefetch, through the existing HTTP client with a timeout, no redirects, a size limit and one download per item at a time; a newer scan cancels the older download. Caches under `%LOCALAPPDATA%\Blackgrid\item-icons\` to keep load off tarkov.dev: an icon stays until its `iconLink` changes, with no time-based expiry. At most once every 30 days a shown icon is revalidated with its ETag (an unchanged icon costs a `304`). A failed download is not retried for 24 hours. Least-recently-used eviction starts only above a 64 MB budget (icons are about 3 KB, so the whole catalog is about 15 MB). Amends the M1 plan's "no item artwork" rule (KTD8) and adds a notices entry: the icons are Battlestate game renders hosted by tarkov.dev, used at the user's direction and downloaded rather than shipped. Needs change 1.
3. `design-map-marker-icons` - explores how to make our own icons and produces the set. Hand-drawn SVG vectors come first; ChatGPT image generation is allowed for concepts, redrawn as vectors. One icon per marker category in one consistent style, readable at 24 px on the dark map, with colours that keep each category's meaning. The user picks from rendered previews, and each file's provenance is recorded (own work, or AI-assisted with the tool named). Independent.
4. `add-map-marker-icons` - maps each marker category to its icon and draws it in place of the placeholder ring, keeping selection, dimming, highlighted exits and pins. Adds a check that every bundled map icon has a provenance entry. Needs change 3.
5. `redo-marker-preferences` - a uniform grid of clickable icon tiles with readable labels, in place of the raw-key chips. Needs change 4.
6. `polish-requirement-rows` - makes the Requirements & uses panel readable ([#43](https://github.com/sh1ny/blackgrid/issues/43)). The normalizer keeps the product or offered item and count, station and level, trader and `minTraderLevel` and task unlock on `ItemRequirement` as optional references instead of the raw `craft <id>` label, resolved through the existing label dictionaries. Rows show a kind tag, a human state (`Needed now`, `Optional use`), `Needs N`, `remaining` only when known, the reason without the repeated source name, and the FIR line only when it says something; craft and barter rows collapse under `Optional uses (N)` after the obligations. Display only: `NeedState`, the decision rules and the catalog's integrity checks do not change. Its PR closes #43. Independent.
7. `plain-language-pass` - rewrites the remaining player-facing strings across Scanner, Map, the decision card, Settings and the shell; maps enums and category keys to labels; moves developer detail behind Details or a diagnostics setting. Needs changes 1 and 6 (change 6 already covers the requirement rows).

## Next: M4.6 - open-issue sweep

Runs after M4.5 and before M6, so every open GitHub issue is judged before a release. Decided with the user on 2026-10-19. No issue is accepted in advance: each is judged when the sweep starts, against `main` at that time, not against the review that filed it. Issues a milestone already names (such as #41 and #43) stay with that milestone.

**Exit criteria:**
- Every open issue not already assigned to a milestone has a verdict agreed with the user, recorded on the issue with its reason: fix now, defer to after 1.0, or close. (agent proposes; user decides)
- An issue that no longer applies (already fixed, code rewritten, premise wrong or superseded by a later decision) is closed with the evidence. (agent)
- An issue that still applies but is too minor or too unlikely to matter before 1.0 is deferred to after 1.0, not fixed. (agent)
- Each "fix now" issue is closed by the PR of the change that fixes it, with a regression test at the lowest layer that reproduces it. No fix weakens an integrity, ownership or safety check. (agent)

**Changes** (in order):
1. `sweep-open-issues` - lists the open issues, re-checks each against current `main` (does the cited code still behave that way, is it reachable, how likely and how bad is it) and proposes a verdict for each. The user decides. The agreed fixes are then added to this list as small changes, grouped by area, each naming the issues its PR closes. A roadmap edit, not a code change.
2. The fix changes the sweep adds. Their number and scope are not known until it runs.

## Release versioning (`add-release-versioning`)

Decided with the user on 2026-10-08 and recorded in [ADR-0009](../docs/adr/0009-release-versioning.md): SemVer `v` tags, one minor version per milestone close (M2 → `0.2.0`), `-beta.N` prereleases for user-only checks, a commit-count build number, and a changelog with one entry per merged PR.

Release flow (local, no CI; details in the [README](../README.md)):

- `mise run release:prepare -- <version>` - checks a clean, current `main`, runs the offline gates, then commits `chore(release): v<version>` on `release/v<version>`.
- `mise run release:tag` - after the release PR merges, tags the merge `v<version>` and pushes the tag as the configured GitHub login.
- `mise run build:release` - builds the Windows Release bundle with the version and build number, then runs `bundle:check`.
- `mise run release-notes -- --unreleased` - previews the next release's entries.

Installers, GitHub Releases, code signing and CI builds belong to M6.
